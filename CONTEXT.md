# MemeOver context

MemeOver puts Discord media, text and reactions over a player’s desktop. Streaming is optional. The Discord bot admits events for a guild and sends them to joined players over WebSocket. The desktop app owns local display, moderation controls and settings.

## Playback destinations

| Surface | Behavior that matters when changing it |
| --- | --- |
| Desktop overlay | Transparent, click-through Tauri window. Plays its own queue. Local Discord history and Replay follow desktop playback. Desktop mute affects its own output. |
| Browser source (OBS and other streaming software) | The optional loopback server serves a transparent page. It joins the bot with its own socket and plays its own queue. It shares the desktop renderer. The two queues can play at different times. Skip, clear and moderation reach a loaded source. |
| Twitch Alpha | The optional account connects in the desktop app. The overlay owns EventSub and token refresh. Twitch events feed the desktop only and stay out of history. The [browser relay study](docs/twitch-browser-source-spike-2026-11-16.md) is a proposal. |

**Stream only** suppresses desktop media, text, reactions, sound, history recording and Replay while the browser source is enabled. If OBS closes or the source fails, desktop playback stays suppressed. Deliberately disabling the browser source restores it immediately. See [destination policy](app/src/shared/stream-destination.ts).

**Current settings** links follow display edits live. Saved/default profiles and older links keep a snapshot. To opt an older OBS source into live changes, replace its URL once in the existing scene. The link also captures the desktop overlay’s reference screen size. Copy a fresh URL after a connection change or a move to a differently sized screen. Treat the complete URL as a credential. See [source configuration](app/src/shared/browser-source.ts) and the [streaming guide](README.md#browser-source).

## What belongs on screen

| Surface | Shipped design decision |
| --- | --- |
| Settings | The operator sees controls and persistent status here. A guild pause appears beside the [overlay controls](app/src/windows/settings/components/overlay-form/sections/overlay-controls.tsx). Tab content switches immediately while the [active tab indicator](app/src/windows/settings/components/tab-nav.tsx) can move. |
| Desktop overlay | Media and reactions appear over the user’s activity. A guild pause leaves the overlay free of banners. Enabled arrival notifications can still appear during a pause and respect the user’s duration and corner. [Notification regressions](test/browser/notifications.spec.ts) |
| Browser source | Viewers see the media on a transparent scene. Desktop and source share the [media stage](app/src/windows/overlay/OverlayStage.tsx). The [source page](app/src/windows/browser-source/BrowserSourceApp.tsx) owns the temporary preview aids. |
| Site | Explain shipped behavior to prospective users. Both languages share the [home page](site/src/components/home-page.astro). Describe which player receives a feature when that affects what viewers will see. |

## Domain Terms

- **Setup code**: a pasteable connection payload generated by the Discord bot and consumed by the desktop app. It carries the guild id, token, and WebSocket URL needed for the overlay to join a registered guild.
- **Settings window**: the desktop window for connection, display and server configuration.
- **Profile**: a named snapshot of `OVERLAY_PROFILE_FIELDS`, excluding connection credentials and machine preferences.
- **Guild room**: the bot's per-guild set of joined WebSocket clients in `bot/src/utils/store.ts`.
- **Registry**: persisted guild configuration in the SQLite database `data/memeover.db` (WAL), relative to the bot working directory (or `MEMEOVER_DATA_DIR` for isolated tests). Reads are served from memory; the legacy import is tracked in SQLite, so a failed rename of `guilds.json` cannot trigger a second import.
- **Source `bot_app`**: messages and reactions originating from bots/apps, controlled by the server's `/memeover bots` policy and the client's display preference.
- **Anonymous media**: `/memeover secret` media with `anonymous: true`; attribution is hidden.
- **Server creator**: the app's guided installer and managed process for a self-hosted bot.
- **Display queue**: the bounded FIFO of `DisplayQueueItem`s waiting to appear.
- **Floating reaction**: a short-lived emoji animation rendered independently of the display queue.
- **Reaction budget**: weighted admission with FIFO eviction to bound reaction scene complexity.
- **Guild pause**: an admin-controlled persisted `paused_until`; the bot drops new events and the overlay clears its waiting queue; explicit history replays can still play when desktop playback is enabled.
